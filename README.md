# Autotechno integration: Zoho CRM · ClickUp · Balance · Power BI

One Flask middleware on Render connects the four systems. Systems never call each other
directly: all rules, ID links, logs and history live here and in PostgreSQL.

```
Website ──lead──▶ Zoho CRM ◀──deals / stock──▶ ┌──────────────────────┐ ◀──statuses──▶ ClickUp
                                               │ middleware + Postgres │
Balance (1C) ──── read only ─────────────────▶ └──────────────────────┘ ──analytics──▶ Power BI
```

| Flow | What | Trigger | Code |
|---|---|---|---|
| F1 | Balance items, prices, stock → Zoho Products + dwh | every 15 min | `flows/f1_products.py` |
| F2 | Balance client debts → Zoho Accounts/Deals + ClickUp "paid" | every 30 min | `flows/f2_balances.py` |
| F3 | Zoho deal stage → ClickUp execution tasks | Zoho webhook | `flows/f3_deal_stage.py` |
| F4 | ClickUp task status → Zoho `INT_Execution_Status` | ClickUp webhook | `flows/f4_task_status.py` |
| F5 | Deals, tasks, sales, stock history → dwh for Power BI | hourly / nightly | `flows/f5_dwh.py` |
| F6 | Website form → Zoho lead | Gegidze Consulting webhook (not in this service) | — |
| F7 | Supplier contracts → 5% / 15% / 80% payment subtasks + reminders | ClickUp webhook + daily 09:05 | `flows/f7_supplier_payments.py` |

## Rules that are never broken

- **Balance is read only.** `clients/balance.py` has no write method; a test fails if one appears.
- **Zoho: only `INT_*` fields are written.** `update_deal` / `update_account` reject anything else.
  Stage and the Gegidze configuration are never touched.
- **One source per data item.** Items/prices/stock/debts → Balance; leads/deals → Zoho; tasks → ClickUp.
- **Idempotent.** Replaying any event or rerunning any job creates no duplicates
  (`ops.id_map` unique keys, `ops.inbound_event` dedupe, cursors moved in the same transaction as data).

## Deploy on Render

1. **Blueprint:** Render → New → Blueprint → this repo. `render.yaml` creates the web service
   (Starter, always on) and PostgreSQL (Basic-256mb) in one region. Migrations run on every
   deploy (`preDeployCommand`).
2. **Environment:** fill every variable marked `sync: false` (list with comments: `.env.example`).
   `INBOUND_TOKEN` is generated by Render.
3. **Zoho:**
   - API Console → Self Client (Autotechno admin account) → scopes
     `ZohoCRM.modules.ALL,ZohoCRM.settings.fields.READ,ZohoCRM.coql.READ` → refresh token.
   - Create fields: Deals `INT_ClickUp_Task_IDs` (text), `INT_Execution_Status`
     (picklist: არ დაწყებულა / მიმდინარე / შესრულებულია), `INT_Paid` (checkbox);
     Products `INT_Balance_Code` (text, unique), `INT_Stock` (decimal), `INT_Last_Sync` (datetime);
     Accounts `INT_Balance_Debt` (currency). Make `Identification_Code` mandatory.
   - Org variable `INT_TOKEN` = value of `INBOUND_TOKEN`.
   - Function from `zoho/INT_notify_middleware.dg` + workflow rule `INT_Stage_To_Middleware`.
4. **ClickUp:**
   - Execution space with lists and custom fields `Zoho Deal ID`, `Zoho Deal URL`, `Template`, `გადახდილია`.
   - Contracts list with fields `მწარმოებელი`, `კონტრაქტის ნომერი`, `კონტრაქტის თანხა`, `ვალუტა`,
     `კონტრაქტის თარიღი`, `პორტში მიწოდების თარიღი`, `15%-ის გადახდის თარიღი`,
     `80%-ის ვადა კონტრაქტით, დღე` (names must match exactly; fields are found by name).
   - Fill list ids in `db/seed_task_templates.sql`, then `psql "$DATABASE_URL" -f db/seed_task_templates.sql`.
   - Render Shell: `python -m scripts.register_clickup_webhooks https://<service>.onrender.com`
     → put both printed secrets into Environment.
5. **Balance:** enable web-service export, create the exchange node and a read-only user,
   export the JSON descriptions into `docs/balance/`, then confirm the field names in
   `balance_schema.py` and `BALANCE_CHANGE_HEADER`.
6. **First load:** Render Shell → `python -m scripts.backfill --sales 2024-01-01 --contracts`.
7. **Power BI:** `ALTER ROLE pbi_reader PASSWORD '...';` (psql, not in git), allow the gateway IP
   in the database access list, connect with the PostgreSQL connector (SSL, Import) to `bi.*` views.

## Operations

| | |
|---|---|
| Health | `GET /health` |
| Log | `GET /admin/log?flow=F1&limit=50` with header `X-Int-Token` |
| Run a job now | `POST /admin/run/<job>` with `X-Int-Token` (job names in `scheduler.py`) |
| Switch a flow off | env `FLOW_F3_ENABLED=false` (also `F1 F2 F4 F5 F7`) |
| Alerts | >10 failures/hour or F1 stale 2 h → task in `CLICKUP_INCIDENTS_LIST_ID` |
| Retention | `ops.sync_log` and processed events older than 90 days are deleted nightly |
